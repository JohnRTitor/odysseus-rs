# Python baseline — **NOT CAPTURED (unavailable)**

Task **T0120**: "Capture the Python baseline into `docs/baseline/`: idle RSS,
`GET /` TTFB, startup, endpoint-mix `oha`, streaming chunk latency."

**Status: UNAVAILABLE.** Recorded rather than omitted, and **not estimated**.
`AGENTS.md` N7 is about falsifiability, and a file that quietly contains no
Python numbers would be indistinguishable from one where they were measured and
found flattering.

## Why

The Python application cannot be run on this machine.

| Check | Result |
|---|---|
| Interpreter on `PATH` | **none** — `python`, `python3`, `python3.12`, `python3.13` are all absent |
| Interpreter anywhere | `/home/masum/.local/share/uv/python/cpython-3.14.7-linux-x86_64-gnu/bin/python3.14` — a bare CPython 3.14.7 |
| `fastapi`, `uvicorn`, `sqlalchemy`, `chromadb` | all `ModuleNotFoundError` in that interpreter |
| Virtualenv in the project | **absent** — no `odysseus/.venv` |
| `Python/devenv.nix` | provides only `pkgs.tk` and `git` — no interpreter, none of the ~200 requirements |
| Load generators | `oha`, `hey`, `ab`, `wrk` all absent |

So none of the four §0.1 measurements is possible: the app cannot import, the
server cannot bind, and there is no `oha` to drive it if it could.

## What this costs

The comparison half of every future performance claim. The Rust numbers in
`2026-10-04-rust.json` exist; there is nothing to compare them to. Until this is
captured:

- **No "Rust is N× faster than Python" statement is supportable.** Any such
  claim is currently unfalsifiable, which is exactly what N7 forbids.
- `PERFORMANCE_PLAN.md` §5.2's threshold re-tuning for the vector work, and the
  `INCOMPLETE.md` estimates that reference Python behaviour, rest on reading the
  source rather than on measurement. Reading is a weaker instrument and should be
  described as such.

## What capturing it needs

1. An interpreter with the app's requirements installed. The Python tree has a
   `devenv.nix` that does not currently provide one; either a
   `devShells.default` with `python3` + `requirements.txt`, or a `uv`/`venv`
   bootstrap.
2. A load generator. `oha` is the cheapest of the four named in §0.1 and is a
   single static binary.
3. A populated `data/` directory. The baseline should be taken against a
   representative dataset, not an empty one — idle RSS of an empty database is
   not a number worth recording.
4. A GPU **not** required for the four §0.1 items; all are CPU-only.

## Recording it later

Add `docs/baseline/<date>-python.json` with the same schema as
`2026-10-04-rust.json` (`machine`, `startup`, `memory`, `load`, `unavailable`),
so the two are directly comparable. Note in the file which interpreter,
dependency set and dataset were used — a Python baseline without those is as
unfalsifiable as no baseline at all.
